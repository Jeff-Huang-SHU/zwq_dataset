## 一、数据与目标对齐（必读）

### 1.1 `new_data.json` 结构（只读理解）

- 顶层为 **JSON 数组**，每条为对象，字段包含：`register`、`tittle`、`content`、`model`、`generation`（字段名与拼写以文件为准，**不得改写**）。
- **人类文本**：`"model": "h"`（抽样统计约 500 条）。
- **机器文本**：`model != "h"`（约 13500 条）。
- **成组关系**：约 **505** 个不同 `tittle`，其中约 **499** 个标题下同时存在 1 条人类与多条机器；多数标题下机器条数约为 **27** 条/标题（分布以实际解析为准）。这与原版 Fast-DetectGPT 使用的「等长 `original[]` / `sampled[]` 一一配对」需在**适配层**显式构造，而不是改源 JSON。

### 1.2 原版计算逻辑（必须保持一致的部分）

以下须与 `fast-detect-gpt/scripts/fast_detect_gpt.py` 中实现**数值与公式一致**（通常通过**直接 import 或复制未改动的函数**保证）：

- 条件概率曲率 / **sampling discrepancy**：`get_sampling_discrepancy_analytic`（论文高效形式，对应 `--discrepancy_analytic`）或原版蒙特卡洛 `get_sampling_discrepancy`（若论文复现指定解析式，应以前者为主并与 `gpt3to4.sh` 一致）。
- 对每条文本：用 **scoring 模型** 与 **sampling/ref 模型** 得到 `logits_ref`、`logits_score`、`labels` 的方式与白盒/黑盒分支一致。
- **ROC / PR 曲线及 AUC**：与 `scripts/metrics.py` 中 `get_roc_metrics`、`get_precision_recall_metrics` 一致（基于 `real_preds` + `sample_preds` 的拼接标签约定）。

### 1.3 指标范围说明（避免「口头复现」歧义）

原版 `fast_detect_gpt.py` 主流程输出 **ROC-AUC** 与 **PR-AUC**，**不直接输出**固定阈值下的 precision / recall / F1。

| 指标 | 与原版关系 | 建议做法 |
|------|------------|----------|
| AUC | ROC-AUC 与原版一致；可另报 PR-AUC 与原版 JSON 字段一致 | 直接复用 `metrics.py` |
| Precision / Recall / F1 | 需在**连续 criterion** 上选定**单一阈值**二值化后计算 | 在 `versions` 中增加**后处理**脚本：阈值来源写清楚（如 Youden 指数、使 F1 最大的 dev 集搜索、或固定分位数），并在文档中固定，保证可复现 |

## 三、各任务执行原因（Why）

| 任务 | 原因 |
|------|------|
| T0 | 依赖版本漂移会改变 logits 与 AUC，难以判断是数据适配问题还是环境差异。 |
| T1 | `fast_detect_gpt.py` 只认 `load_data()` 读入的 `original`/`sampled` 列表；在**不改** `new_data.json` 的前提下，必须在内存或中间文件（若写中间文件，须新路径，不覆盖源 JSON）完成映射。 |
| T2 | 数据非「天然一行一对」；配对规则若不文档化，指标无法复现且易与论文设定不一致。 |
| T3 | 中文模型常混用不同 tokenizer；原版对黑盒要求 ref 与 score 的 **shifted labels 对齐**，这是常见失败点。 |
| T4 | 「逻辑完全一致」指**判别量定义与循环结构**一致；通过薄封装避免在主线 `scripts/` 上打补丁，满足「保留原始代码」。 |
| T5 | 用户要求尽可能中文模型以减轻域偏移；模型过小会导致曲率信号弱、AUC 偏低。 |
| T6 | 全量 1.4 万条 × 双模型前向成本高，冒烟可尽早暴露形状/设备/对齐错误。 |
| T7 | 与论文仓库对齐的 JSON 便于用现有 `report_results.py` 或二次分析。 |
| T8 | 用户明确要求 F1 等；必须在不篡改核心 criterion 的前提下，在**决策层**补指标。 |
| T9 | 证明适配层未破坏原版算法；这是最强的回归检查。 |

## 四、每一步正确性检查（How to verify）

### T0 环境快照

- **检查**：`python -V`、`pip show torch transformers` 与快照文件一致；`CUDA_VISIBLE_DEVICES` 与显卡型号记录。
- **通过标准**：任何人按快照可重建环境；全量实验记录同一快照 ID。

### T1 数据加载与结构

- **检查项**：
  - 记录总数：人类 500、机器 13500、数组总长 14000（或与实际文件一致）。
  - 随机抽 10 个 `tittle`，人工确认：配对的人类 `content` 与机器 `content` 确属同一标题语义组。
  - 构造后 `len(original) == len(sampled)`，且均 > 0。
- **通过标准**：无缺失配对（或缺失规则在 `PAIRING_SPEC` 中显式列出且计数闭合）。

### T2 配对策略

- **检查项**：对展开后的每一对 `(original[i], sampled[i])`，`original[i]` 的 `model` 语义上为人类（`h`），`sampled[i]` 为非 `h`。
- **通过标准**：抽样 100 对自动化断言 + 1 次人工 spot-check。

### T3 Tokenizer / 对齐

- **检查项**：与原版相同断言路径下不触发 `Tokenizer is mismatch`；若两模型词表不同，须有单独文档说明是否采用「仅用 scoring tokenizer 截断再编码」等策略，并用 T9 子集对照验证 AUC 是否异常偏离。

### T4 薄封装评估

- **检查项**：
  - 对**单条**文本，直接调用原版 `get_sampling_discrepancy_analytic`，与 `scripts/fast_detect_gpt.py` 内嵌调用结果一致（同一模型权重、同一输入）。
  - `predictions['real']` 与 `predictions['samples']` 长度等于配对数。
- **通过标准**：与原版函数 bitwise 同一逻辑路径（diff 仅数据源）。

### T5 中文模型

- **检查项**：模型卡与许可证合规；`from_pretrained` 可加载；显存峰值可接受。
- **通过标准**：smoke AUC 显著优于随机（如 > 0.55）或不低于选定英文小模型基线（作为工程 sanity check，非论文结论）。

### T6 Smoke

- **检查项**：日志无 exception；单卡可完成；输出 JSON 可被 `json.load`。
- **通过标准**：10 分钟内结束 smoke；指标为有限数。

### T7 全量

- **检查项**：`metrics` 中 `roc_auc` 与手算 `sklearn.metrics.roc_auc_score`（注意标签构造与 `metrics.py` 一致）一致。
- **通过标准**：结果文件路径、种子、模型名写入 JSON 或 sidecar meta。

### T8 Precision / Recall / F1

- **检查项**：
  - 明确写出：分数越高越倾向「机器」还是「人类」，与 `roc_curve` 正类定义一致。
  - 用同一阈值在 dev 上选、在 test 上评，避免信息泄漏（若只有一套数据，须说明采用固定阈值如 0.5 分位或 Youden on 全数据并声明乐观偏差）。
- **通过标准**：`f1 = 2*p*r/(p+r)` 与 sklearn `f1_score` 一致；随机种子固定可复现。

### T9 与官方数据子集对照

- **检查项**：从 `exp_main/data` 或 `exp_gpt3to4/data` 取一小段已存在 `raw_data.json`，用 `versions` 入口与**原始** `python scripts/fast_detect_gpt.py ...` 各跑一遍，比较 `roc_auc`（允许极小数值差）。
- **通过标准**：差异 < 1e-4 或可归因于 fp16 非确定性并记录在案。

## 五、风险与依赖（实施时留意）

1. **原版 `scripts/fast_detect_gpt.py` 中 `load_tokenizer` 调用参数个数**与 `model.py` 定义是否一致，若运行报错需在 `versions` 侧修复封装或固定 fork，**勿静默改坏原版语义**。  
2. **长中文文本**：注意 `max_length` 与显存；若截断，须与原版 `experiment` 使用的 tokenizer 参数一致并记录。  
3. **指标解读**：多模型、多 `generation` 类型混合时，整体 AUC 反映「人类 vs 全机器池」；若需按 `register` / `model` 分层报告，在 T8 增加分组统计（不改变核心 criterion）。
