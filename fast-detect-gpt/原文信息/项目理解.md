# Fast-DetectGPT 项目理解（工作目录：`/home/hjf/A_workspace/fast-detect-gpt`）

本文档概括仓库结构、研究背景、目标、技术栈，以及典型输入与输出，作为后续开发与实验的上下文基础。

---

## 1. 项目背景

**Fast-DetectGPT** 是 ICLR 2024 论文 *「Fast-DetectGPT: Efficient Zero-Shot Detection of Machine-Generated Text via Conditional Probability Curvature」* 的官方实现，在 [DetectGPT](https://github.com/eric-mitchell/detect-gpt) 思路上做了借用与扩展。

核心问题：**在零样本（无需在标注数据上训练分类器）前提下，判断一段文本更可能来自人类还是机器生成。** 与 DetectGPT 相比，论文强调在保持或提升检测效果的同时，通过**条件概率曲率 / 采样差异**的解析形式大幅压缩计算量（README 中报告约 **340×** 加速量级，具体依赖硬件与设置）。

论文与资源：

- 论文：<https://arxiv.org/abs/2310.05130>
- OpenReview：<https://openreview.net/forum?id=Bpcgcr8E8Z>
- 在线 Demo：<https://fastdetect.net/>

## 2. 项目要达成的目的

1. **复现与评估**：在公开数据集（如 XSum、SQuAD、Writing、PubMed 等）上，对「人类原文 vs 某源模型续写/生成」成对样本计算检测指标（ROC AUC、PR AUC 等）。
2. **方法对比**：除 Fast-DetectGPT 外，脚本中还包含 DetectGPT、DetectLLM、DNA-GPT 及多种 baseline（见 `scripts/baselines.py` 等），便于横向对比。
3. **白盒与黑盒**：
   - **白盒**：采样模型与打分模型为同一 LM（`sampling_model_name == scoring_model_name`）。
   - **黑盒**：用替代模型对参考分布与打分分布建模（例如用 `gpt-j-6B` 采样、`gpt-neo-2.7B` 打分），检测非开源或异构源模型生成文本。
4. **可交互试用**：`scripts/local_infer.py` 从终端读入用户文本，输出判别统计量与「机器生成」概率估计（基于预拟合的高斯分布参数，见该脚本内注释）。

## 3. 技术栈

| 类别 | 说明 |
|------|------|
| 语言 | Python 3（README 写明实验环境为 Python 3.8；仓库内可见 `.venv` 使用 3.12，以实际环境为准） |
| 深度学习 | PyTorch、`transformers`（`requirements.txt` 固定为 **4.28.1**） |

## 5. 基本输入与输出

### 5.1 数据构建（`scripts/data_builder.py`）

- **输入（CLI 主要项）**：`--dataset`、`--n_samples`、`--base_model_name`（本地因果 LM），或 `--openai_model` + `--openai_key`（及可选 `--openai_base`）等。
- **输出（文件前缀为 `--output_file`）**：
  - `<prefix>.args.json`：运行参数快照。
  - `<prefix>.raw_data.json`：**下游评估统一读取的数据**。内容包含人类段落与模型生成段落的配对列表（字段名在代码中为 `"original"` / `"sampled"` 等结构，与 `load_data()` 一致）。

### 5.2 Fast-DetectGPT 批量评估（`scripts/fast_detect_gpt.py`）

- **输入**：
  - `--dataset_file`：上述 **去掉后缀** 的路径前缀（脚本内部会拼接 `.raw_data.json`）。
  - `--sampling_model_name` / `--scoring_model_name`：参考分布与打分用的 LM（可相同或不同）。
  - `--discrepancy_analytic`：使用论文中的**解析形式**（`sampling_discrepancy_analytic`）；不加则走蒙特卡洛采样版 `sampling_discrepancy`（更慢）。
  - `--device`、`--cache_dir`、`--seed` 等。
- **输出**：
  - `<output_file>.sampling_discrepancy_analytic.json` 或 `<output_file>.sampling_discrepancy.json`。
  - JSON 内包含：`predictions`（人类/机器两类上的标量 criterion 列表）、`metrics`（含 `roc_auc`、`fpr`、`tpr`）、`pr_metrics`、`raw_results`（逐条文本与分数）等。

### 5.3 本地交互 Demo（`scripts/local_infer.py`）

- **输入**：命令行指定 `--sampling_model_name`、`--scoring_model_name` 等；运行后从标准输入读入多行文本（空行结束一段）。
- **输出**：打印 **criterion** 数值，以及基于内置高斯近似的 **P(机器生成)** 百分比（仅对脚本中已写死的若干模型对有参数表；更换模型组合需自行标定或改写 `distrib_params`）。

### 5.4 Shell 流水线

- **`main.sh`**：`exp_main/data` 下为 `xsum/squad/writing` × 多个源模型生成数据；`exp_main/results` 下依次跑 Fast-DetectGPT、baselines、DNA-GPT、DetectGPT、DetectLLM，并包含黑盒设定（如 `gpt-j-6B` + `gpt-neo-2.7B`）。
- **`gpt3to4.sh`**：`exp_gpt3to4`，需配置 OpenAI Key；数据为 `davinci` / `gpt-3.5-turbo` / `gpt-4` 等；评估阶段对 Fast-DetectGPT 使用 `--discrepancy_analytic`（与论文高效形式一致）。

---

## 6. 方法要点（实现层面）

- **检测统计量**：对序列上每个位置，结合 **参考模型** 的分布与 **打分模型** 对真实 token 的对数概率，构造与 DetectGPT「曲率」思想相关的 **sampling discrepancy**；`get_sampling_discrepancy_analytic` 用参考分布的均值/方差闭式表达，避免大量重复采样。
- **阈值与曲线**：将 criterion 看作分数，在人类与机器两组样本上计算 ROC/PR，结果写入上述 JSON。
